# ADR-036: ADR Catalogue Lives in README via Generator Script + CI Sync Gate

**Status**: Accepted
**Date**: 2026-05-31
**Phase**: 10

## Context

REQ-DOC-02 requires ADRs to be surfaced in README so a recruiter scanning the repo entry point sees the decision catalogue without needing to navigate into `.planning/`. After Phase 10 closes, the repo holds 37 ADRs spanning 10 phases — a number large enough that hand-maintaining a README table is guaranteed to drift the first time a new ADR lands and the README forgets to add the row. The submission cannot ship with one missing or stale row; "I forgot to update the index" reads as carelessness during the recruiter's arguição.

The 10-CONTEXT decision D-08 places the catalogue in README; the open question is whether the table is hand-maintained, lives in a separate `.planning/adrs/INDEX.md` with a README link, or is generated by a script from ADR file metadata. Three forces shape the answer. First, the README is the recruiter's first surface — eyes spend more time there than in `.planning/`, so the catalogue belongs in README, not behind a link. Second, hand-maintenance is the failure mode the GSD workflow has explicitly avoided everywhere else (ROADMAP plan counts are sourced from disk, REQUIREMENTS coverage is computed, STATE position is advanced by SDK verbs); a hand-maintained ADR table would be the only doc surface that drifts. Third, CI is the natural enforcement point — Plan 10-08 already ships `.github/workflows/ci.yml`, and a one-line `bun run docs:adr-index:check` step makes drift impossible to merge.

The script-output insertion needs a deterministic boundary. Embedding the table directly into freeform README content would force the generator to either rewrite the whole file (too destructive — operator changes elsewhere collide) or guess at boundaries (fragile — heading regex hits any "## ADR" string). Sentinel markers (`<!-- ADR-INDEX:START -->` / `<!-- ADR-INDEX:END -->`) are the canonical solution: they are HTML comments invisible in rendered markdown, they survive arbitrary README restructuring, and they make the generator's contract one operation — "replace bytes between these two markers, throw if absent".

The ROADMAP anticipated this under the label "ADR-029" (Phase 10 catalogue), but Phases 5/6/7/8/9 consumed 019..034 before Phase 10 closed; the decision takes the next-free number ADR-036 with the renumber note recorded in Phase 10's closeout.

## Considered

- **Option A — Generated table between sentinel markers in README, regenerated via `scripts/build-adr-index.ts`, CI gates drift with `bun run docs:adr-index:check` (chosen, locked by Plan 10-09 Task 1)** — script reads `.planning/adrs/ADR-*.md` filenames matching `/^ADR-\d{3}-/`, parses each file's first `# ADR-NNN: Title` line plus `**Status**` / `**Date**` / `**Phase**` lines, renders a markdown table sorted by ADR number, replaces bytes between the sentinel markers in README; `--check` mode computes the would-be README and exits non-zero on drift without writing. CI workflow runs `bun run docs:adr-index:check` after typecheck and fails the build if README is stale. Pros: zero hand-maintenance; CI gate makes drift impossible to merge; sentinel markers survive arbitrary README restructuring; the ADR file format (Status / Date / Phase header lines + `# ADR-NNN: Title` first line) is already the locked CLAUDE.md template, so no metadata schema is new; the script is ~120 lines of pure Bun, no dependencies, no build step. Cons: the ADR frontmatter format is now load-bearing — a future plan that wants to change the Status/Date/Phase header structure must also update the parser; the script must be re-run by the author when a new ADR is added (CI tells them via the gate, but the local feedback loop is one extra command).
- **Option B — `.planning/adrs/INDEX.md` only, with a one-line link from README** — keep the catalogue under `.planning/adrs/` (where the ADR files live) and let the README link `[ADR catalogue](.planning/adrs/INDEX.md)` point to it. Pros: catalogue lives next to the ADR files (cohesion); shorter README. Cons: recruiter eyes don't leave the README page — clicking through to a subdir for a list of decisions is unnecessary friction; the catalogue is the most-asked-for surface during the arguição ("walk me through your decisions") so it needs to be the most visible; foreclosed by D-08 ("ADR catalogue lives in the README").
- **Option C — Hand-maintained markdown table in README** — author manually adds a row to the README table every time a new ADR is committed. Pros: zero infrastructure; no script to maintain; full control over row ordering and formatting. Cons: drift is inevitable — the first time a Phase 11 ADR lands and the README forgets the row, the catalogue is incomplete; "one missing row signals carelessness" during the recruiter's arguição; no CI enforcement is possible without effectively rebuilding Option A's script; the GSD workflow has avoided hand-maintained doc tables everywhere else (ROADMAP counts, REQUIREMENTS coverage, STATE position) and this would be the only exception; foreclosed by drift-inevitability.

## Decision

**Option A — Sentinel-marker (`<!-- ADR-INDEX:START -->` / `<!-- ADR-INDEX:END -->`) generated table in README, regenerated by `scripts/build-adr-index.ts` reading `.planning/adrs/ADR-*.md` metadata, with `bun run docs:adr-index:check` running in CI as a drift gate.** Option B is rejected because the catalogue is a recruiter-first surface that belongs on the README page, not one click away. Option C is rejected because hand-maintenance drift is inevitable and would be the only hand-maintained doc surface in the GSD workflow.

The locked implementation is the 10-09 Task 1 wiring:

- `scripts/build-adr-index.ts` (Plan 10-09 Task 1) exports `parseAdrFile`, `readAdrs`, `renderTable`, `replaceBetweenMarkers`, `START_MARKER`, `END_MARKER` for unit testability; the CLI entry point reads the canonical paths (`ADRS_DIR = .planning/adrs/`, `README_PATH = README.md`), generates the table, and either writes (`bun run docs:adr-index`) or compares-and-exits (`bun run docs:adr-index:check`).
- `scripts/build-adr-index.test.ts` (Plan 10-09 Task 1) covers 7 behaviors against tempdir fixtures: parseAdrFile happy path + malformed-status fallback to `(unknown)`; readAdrs sort-by-number; renderTable header + 3 sorted rows with `[Title](.planning/adrs/<slug>.md)` links; replaceBetweenMarkers byte-stable outside markers; replaceBetweenMarkers throw when markers absent; readAdrs ignores non-matching files.
- `package.json` (Plan 10-09 Task 1) — `"docs:adr-index": "bun scripts/build-adr-index.ts"` + `"docs:adr-index:check": "bun scripts/build-adr-index.ts --check"`.
- `.github/workflows/ci.yml` (Plan 10-09 Task 1) — `ADR index sync check` step running `bun run docs:adr-index:check` between Typecheck and Unit tests; fails the build if README ADR table is out of sync with `.planning/adrs/`.
- `README.md` (Plan 10-09 Task 3) — sentinel markers `<!-- ADR-INDEX:START -->` and `<!-- ADR-INDEX:END -->` bracket the ADR Catalogue section; the table content between is regenerated by Task 4's `bun run docs:adr-index` invocation.

### Why NOT INDEX.md only (Option B)

The catalogue is the recruiter's most-asked-for surface during the arguição — "walk me through your architectural decisions" is a near-guaranteed prompt for a senior-level submission. Hiding the list one click behind a README link adds friction precisely where the reviewer needs zero friction. The GSD workflow's reading-order priority is `CLAUDE.md → README.md → STATE.md → PROJECT.md → REQUIREMENTS.md → ROADMAP.md → ADR files`; the ADR catalogue belongs on the README rung, not the `.planning/adrs/` rung.

### Why NOT hand-maintained (Option C)

Drift is empirically inevitable in repos with this many ADRs. The repo will reach 37 ADRs after Phase 10 closes; at one missed row per Phase-11 wave, the catalogue is wrong within one sprint. The fix isn't "remember to update the table" (the GSD workflow has avoided that everywhere else); the fix is to compute the table from the source of truth (`.planning/adrs/*.md`) and gate drift in CI. The cost of writing the script is ~120 lines of Bun + ~150 lines of unit tests, a one-time investment vs the recurring cost of catalogue drift.

## Consequences

- **Locked in (catalogue is in README, generated, gated by CI)**: drift is impossible to merge — any commit that adds an ADR file under `.planning/adrs/` without running `bun run docs:adr-index` will fail CI on the `ADR index sync check` step. The author's local feedback loop is one command (`bun run docs:adr-index`); CI catches the omission if the author skips it.
- **Locked in (sentinel markers `<!-- ADR-INDEX:START -->` / `<!-- ADR-INDEX:END -->`)**: README content outside the markers is byte-stable across regenerations; the script throws if either marker is missing rather than silently producing an empty table. Foreclosed: any README restructuring that wants to relocate the catalogue must move the markers as a pair.
- **Locked in (ADR frontmatter format is load-bearing)**: the parser depends on `# ADR-NNN: Title` as the first non-empty line plus `**Status**: <text>` / `**Date**: <text>` / `**Phase**: <text>` lines somewhere in the file. The CLAUDE.md ADR template already enforces this; a future plan that wants to evolve the template must update both the template and the parser. Malformed files (missing one of the lines) render with `(unknown)` rather than throwing, so a single bad ADR cannot block CI for all the others.
- **Locked in (filename pattern `ADR-NNN-<slug>.md`)**: the regex `/^ADR-\d{3}-[a-z0-9-]+\.md$/` is the canonical match; the parser ignores `README.md`, drafts, and any file that doesn't match. Foreclosed: ADRs over number 999 would require expanding the regex to 4 digits (the submission's expected total is ~40-50, so this is far out of scope).
- **Locked in (script has zero runtime dependencies)**: `node:fs`, `node:path`, `node:url` only — no markdown parser, no YAML lib, no template engine. The script runs on Bun directly without a build step.
- **Locked in (CI gate runs between Typecheck and Unit tests)**: fast-fail position — a stale README short-circuits the workflow before the docker stack boots, saving ~10 min per drift run.
- **Foreclosed (Option B)**: no `.planning/adrs/INDEX.md` file; the README is the single canonical catalogue surface.
- **Foreclosed (Option C)**: no hand-maintained README table; any commit that touches the catalogue must go through `bun run docs:adr-index`.
- **Anticipated recruiter question 1**: "How do you keep the README ADR list from drifting?" — defended: `scripts/build-adr-index.ts` regenerates the table from `.planning/adrs/` on every run; `bun run docs:adr-index:check` is a CI gate that fails the build on drift; the gate sits between Typecheck and Unit tests for fast-fail.
- **Anticipated recruiter question 2**: "Why not just put the catalogue in a subdir?" — defended: the catalogue is a first-surface artifact for the arguição; reducing clicks to zero matters where the reviewer's expected first prompt is "walk me through your decisions"; the GSD workflow's reading order puts the README above `.planning/adrs/` and the catalogue belongs at the README rung.
- **Anticipated recruiter question 3**: "What if an ADR file is malformed?" — defended: the parser fills missing metadata with `(unknown)` rather than throwing; a single bad file degrades one row gracefully instead of blocking the catalogue for all 37 ADRs; the CI gate would still pass on a partially-degraded catalogue, which is correct behavior — the gate's purpose is drift detection, not file-format linting.

Cross-references: ADR-004 (config source-of-truth — same "compute from disk, do not hand-maintain" discipline as Open Configuration Values), Plan 10-09 Task 1 SUMMARY (script + tests + package scripts + CI gate), Plan 10-09 Task 3 SUMMARY (README sentinel markers + Quick Start + Architecture sections); REQ-DOC-02 (ADRs surfaced in README); CLAUDE.md §"ADRs" (the locked template format the parser depends on).

## Alternatives Rejected

- **Option B — `.planning/adrs/INDEX.md` only with a README link** — adds one-click friction precisely where the recruiter's expected first prompt ("walk me through your decisions") needs zero friction; foreclosed by D-08 ("ADR catalogue lives in the README") and the GSD reading-order priority (README is above `.planning/adrs/`).
- **Option C — Hand-maintained markdown table in README** — drift is empirically inevitable in a 37-ADR catalogue; "one missing row signals carelessness"; the GSD workflow has avoided hand-maintained doc surfaces everywhere else and this would be the only exception; the script cost is a one-time investment vs the recurring cost of drift.
