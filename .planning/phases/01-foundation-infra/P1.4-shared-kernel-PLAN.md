<objective>
Ship `@crash/shared-kernel` — the cross-cutting domain primitives package every backend service (and the frontend, via Phase 7) will import. This package contains zero infrastructure imports: no NestJS decorators, no MikroORM, no Socket.IO, no axios. Only the language, dinero.js v2, and zod.

Purpose: REQ-DOM-06 forbids `number` for any monetary amount anywhere in the stack. The `Money` value object — wrapping Dinero v2 around a `bigint` cents representation — is the only legitimate way to represent money. Every later phase consumes it: Phase 3 (wallet balance), Phase 4 (bet amount, cashout), Phase 7 (FE input validation, balance display), Phase 9 (auto-bet strategy math). Errors, event envelopes, branded id types, and the shared env schema ship alongside Money because Phases 2-10 cannot start before these primitives exist.

Output: A workspace package at `packages/shared-kernel/` with a barrel export at `src/index.ts` that re-exports the five subpaths (`money/`, `errors/`, `events/`, `identity/`, `config/`), plus a `tests/money.test.ts` that proves the Money invariants under `bun test`.
</objective>

<interfaces>
The `dinero.js@^2.0.0` (stable, March 2026) package consolidates the previously-separate `@dinero.js/core` and `@dinero.js/currencies` into a single `dinero.js` import. Named functions used by `Money`:

- `dinero({ amount: bigint, currency: Currency<bigint> })` — constructor
- `add(a, b)` — pure addition
- `subtract(a, b)` — pure subtraction
- `multiply(d, factor)` — multiplication; `factor` is either a scalar `number` or `{ amount: bigint, scale: bigint }` (scaled-amount form for rationals)
- `toSnapshot(d)` — returns `{ amount: bigint, currency: Currency<bigint>, scale: bigint }`
- `isNegative(d)`, `isZero(d)`, `equal(a, b)`, `lessThan(a, b)`, `greaterThan(a, b)` — predicates

`Currency<bigint>` shape: `{ code: string, base: bigint, exponent: bigint }`. Per RESEARCH Assumption A3, executor confirms the named export surface against the installed v2.0.x `index.d.ts` and adjusts imports if a name differs — semantics are stable per the v2 announcement.

`zod@^3.23.0` provides `z.object`, `z.string`, `z.enum`, `z.coerce.number`. The `z.coerce.bigint` API may not be in 3.23 (RESEARCH Assumption A7); fallback is `z.string().transform(s => BigInt(s))`. This applies only to env parsing in Phase 1.7 — this plan only ships the shared subset which does not need bigint coercion.
