<objective>
Ship `@crash/contracts` — the cross-stack wire-format package. In Phase 1 the only contract that exists is the `MoneySnapshot` round-trip helper because every other contract (event envelopes in Phase 2, wallet DTOs in Phase 3, bet DTOs in Phase 5, provably-fair algorithm in Phase 4) requires those phases' domain work first. Shipping the skeleton in Phase 1 means later phases drop files into `events/`, `dtos/`, `provably-fair/` without renegotiating paths.

Purpose: The frontend (Phase 7) and the two services need ONE place to import a Money wire-format helper. Putting it in `shared-kernel` would force the frontend to depend on the entire kernel; isolating it in `contracts` keeps the dependency surface small. Phase 4's provably-fair algorithm will live here for the same reason — frontend and backend run the SAME code.

Output: A workspace package at `packages/contracts/` with `serializeMoney`, `parseMoneySnapshot`, and `moneySnapshotSchema` exported. Three placeholder directories with `.gitkeep` files. A test file proving the round-trip and zod-rejection contract.
</objective>

  <action>Create `packages/contracts/src/money/snapshot.ts`:

1. Import `Money, MoneySnapshot, ValidationError, NegativeMoneyError` from `@crash/shared-kernel`. Import `z` from `zod`.

2. Define and export `moneySnapshotSchema`: `z.object({ amount: z.string().regex(/^-?\d+$/), currency: z.string().min(1), scale: z.number().int().nonnegative() }).strict()`. The `strict()` call rejects unknown keys — this matters at the AMQP boundary where a malformed payload from a misbehaving consumer must fail loudly, not silently. The regex on `amount` accepts only integer strings (no decimals, no scientific notation); the minus sign is allowed so that downstream `Money.of` can throw a domain error on negative — separation of concerns: zod validates SHAPE, Money validates DOMAIN.

3. Export `serializeMoney(money: Money): MoneySnapshot` — delegates to `money.toSnapshot()` (which P1.4 already implements). The function is a thin alias for naming/discoverability — calls at the wire boundary should read `serializeMoney(...)`, not `money.toSnapshot()`.

4. Export `parseMoneySnapshot(input: unknown): Money`:
   - Step 1: `const result = moneySnapshotSchema.safeParse(input);`
   - Step 2: if `!result.success`, throw `new ValidationError(`Invalid money snapshot: ${result.error.message}`, result.error)`.
   - Step 3: call `Money.fromSnapshot(result.data)` and return. This call may throw `NegativeMoneyError` for amounts &lt; 0 — propagate the throw (do not swallow into ValidationError).

5. Export the inferred type via `export type MoneySnapshotInput = z.infer&lt;typeof moneySnapshotSchema&gt;;` so consumers in Phase 3+ can type their AMQP payloads against it.
