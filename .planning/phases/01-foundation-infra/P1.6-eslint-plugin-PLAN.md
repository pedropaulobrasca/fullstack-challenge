<objective>
Land the custom ESLint plugin that enforces REQ-DOM-06 ("System represents all monetary amounts using a Money value object [...] no `number` for any amount-like field, anywhere"). Wire it into a flat-config ESLint 9 root configuration. Add a `no-restricted-properties` rule that bans `process.env` access outside `src/config/` and `mikro-orm.config.ts` — the typed env layer is the only sanctioned path.

Purpose: The Money VO from P1.4 is useless if developers can re-introduce `number` for money. ESLint enforcement at build time + CI gates is the only durable defense. The rule must distinguish money-named identifiers (`balance`, `betAmountCents`) from incidentally-typed-number identifiers (`count`, `index`) — over-flagging breaks developer trust; under-flagging defeats the purpose.

Output: A workspace `@crash/eslint-plugin` with the rule, the rule's fixture tests, a root `eslint.config.js`, and a `.prettierrc`. `bun run lint` from repo root succeeds with zero false positives on the existing source tree.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| developer's code → committed git history | The ESLint rule is the gate; bypass via `eslint-disable` would silently reintroduce the disqualifier |
| typed env layer → service runtime | `no-restricted-properties` enforces single-source-of-truth |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01.6-01 | Tampering | Developer reintroduces `number` for money | mitigate | Custom rule with regex matching 12 money words; `error` severity; CI gate in Phase 10 |
| T-01.6-02 | Tampering | `eslint-disable` comments smuggle violations past the rule | mitigate | Code review discipline; future Phase 10 gate adds `--max-warnings 0` and forbids inline disables via `eslint-comments/no-use` (deferred to Phase 10) |
| T-01.6-03 | Information Disclosure | `process.env` access scattered across services | mitigate | `no-restricted-properties` ban + surgical exemption for the config layer + MikroORM CLI config |
| T-01.6-04 | Tampering | Rule false-negative on identifier rename (`totalAmount` → `total`) | accept | Caught in code review; documented as a known limitation in ADR-006 |
| T-01.6-SC | Tampering | New npm install: `@typescript-eslint/rule-tester` | mitigate | Slopcheck in Task 1; same publisher as parser+plugin (already vetted); lockfile-pinned |
</threat_model>
