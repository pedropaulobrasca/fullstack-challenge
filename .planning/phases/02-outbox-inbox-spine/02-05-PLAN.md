<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| AMQP delivery → handler | Broker may redeliver (after consumer crash, after channel close); inbox dedup absorbs the duplicate |
| Handler exception → DLX | A handler that throws is routed to DLX after RMQ_DELIVERY_LIMIT_MAIN attempts; runaway DLQ poison further bounded by RMQ_DELIVERY_LIMIT_DLQ then persisted |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-14 | Tampering | Same message processed twice on broker redelivery | mitigate | Inbox tryClaim INSIDE em.transactional with composite PK; PG unique lock serializes concurrent attempts (02-RESEARCH §Pitfall 3) |
| T-02-15 | Denial of Service | Poison message infinitely retried, hogs consumer slot | mitigate | x-delivery-limit=5 on main queue (buildQuorumArgs in decorator); after 5, broker DLX routes to DLQ |
| T-02-16 | Denial of Service | Poison message in DLQ infinitely re-routed (no DLQ limit) | mitigate | DLQ declared with x-delivery-limit=3 in plan 02-07 (consumer side) — after 3 attempts message DROPPED by broker, BUT our DeadLetterConsumer is itself the consumer of the DLQ and acks after persist, so usually never reaches the 3rd attempt unless dead_letter_messages INSERT fails |
| T-02-17 | Tampering | dead_letter_messages double-write on DLQ redelivery | mitigate | UNIQUE (consumer_name, original_message_id) + ON CONFLICT DO NOTHING |
| T-02-18 | Tampering | Decorator stacking order (RabbitSubscribe wrapping IdempotentSubscribe vs reverse) silently mis-binds | mitigate | Decorator factory composes both: it CALLS RabbitSubscribe internally after replacing descriptor.value, so order is enforced. Verified by plan 02-09 inbox-dedup integration test (assertion: handler called exactly once on broker redelivery). |
| T-02-19 | Information Disclosure | Dead-letter row payload may contain PII in future events | accept | Phase 2 ships no domain payloads; redaction policy deferred to Phase 10 (per 02-RESEARCH §Deferred Ideas) |
</threat_model>
