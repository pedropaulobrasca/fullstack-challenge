- [ ] Plan 04-10 integration suite — frozen env at module-load time + RNG-dependent crashTime cause test isolation failures when files run in sequence. Root cause: src/config/defaults.ts parses process.env at first import and Object.freeze()s the result; subsequent test files that call setupIntegrationEnv overrides (BETTING_WINDOW_MS, GROWTH_RATE) do not take effect because the AppModule reads from the cached frozen env. Each file passes in isolation (bun test path/to/file.ts) but the suite as a whole races. Fix candidates: (a) make env reloadable for tests via a setEnvForTests() helper, (b) move env parsing into Nest ConfigModule with dynamic provider so each AppModule boot picks up current process.env, (c) use AUTO_CASHOUT_MAX_X=2 in tests to bound crashTime regardless of GROWTH_RATE. Out of scope for Plan 04-11 (which only adds smoke probes); flagged for a follow-up 04 hardening plan or Phase 5 entry.
