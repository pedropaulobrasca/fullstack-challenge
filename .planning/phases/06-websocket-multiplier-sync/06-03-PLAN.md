<objective>
Scaffold the WebSocket presentation surface: `JwtIoAdapter` validates JWTs at the handshake (REQ-WS-01), `GameWsGateway` auto-joins each socket to `lobby` + `user:{playerId}` (REQ-WS-02) and emits `round:snapshot` on connect (REQ-WS-04). The snapshot is assembled by a pure `GetWsSnapshotUseCase` that re-queries Round + active bets from the existing repositories.

Purpose: This is the load-bearing wiring for Phase 6. After this plan, the WS endpoint exists and authenticates clients; subsequent plans bolt on tick broadcast (06-04), lifecycle events (06-05), and bet-event bridging (06-06). The gateway is intentionally a thin fan-out — it injects use cases, never repositories directly.

Output: `JwtIoAdapter` + `GameWsGateway` + `GetWsSnapshotUseCase` + zod payload schemas + `main.ts` wires the adapter; `BetRepository.findActiveByRoundId(roundId): Promise<Bet[]>` extension to support the snapshot's masked active-bets list; unit tests cover snapshot assembly, adapter token extraction, and gateway connection.
</objective>

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-05 | Spoofing | JwtIoAdapter handshake middleware | mitigate | `io.use()` runs before `handleConnection`; any verifier rejection calls `next(new Error("UNAUTHORIZED"))` which terminates the upgrade per Socket.IO docs |
| T-06-06 | Information Disclosure | Token in proxy access logs | mitigate | Token extracted from `auth.token` payload or `Authorization` header only — `handshake.query` paths explicitly ignored (PITFALLS H3); unit test (d) enforces |
| T-06-07 | Information Disclosure | Cross-player private events | mitigate | `socket.join(\`user:\${playerId}\`)` derives playerId solely from `socket.data` set by verified JWT; client cannot influence room membership |
| T-06-08 | Tampering | Outbound payload shape | mitigate | All payloads typed against zod schemas in `ws-event.payloads.ts`; future inbound messages (if any) MUST parse via the same schemas |
</threat_model>
