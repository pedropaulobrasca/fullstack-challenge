<objective>
Wire the in-process domain-event hooks: `RoundLoopService` emits `round.started`, `round.running`, `round.crashed`, `round.settled` via NestJS `@nestjs/event-emitter`; `GameWsGateway` `@OnEvent` handlers fan each out as a regular `emit` (NOT volatile) to the `lobby` room. `RoundLoopService` also calls `multiplierBroadcastService.start(roundId)` on RUNNING enter and `multiplierBroadcastService.stop()` BEFORE emitting `round.crashed` (so no spurious post-crash tick leaks past the broadcast loop).

Purpose: REQ-WS-03 requires the gateway to emit `round:started`, `round:running`, `round:crashed`, `round:settled` for every round. Decoupling via `EventEmitter2` (RESEARCH §Pattern 2) avoids a circular dependency between `RoundLoopService` (application/) and `GameWsGateway` (presentation/) — domain doesn't depend on presentation, presentation subscribes.

Output: `EventEmitterModule.forRoot()` registered in `AppModule.imports`; `RoundLoopService` extended with `EventEmitter2` injection + four emit calls + multiplier broadcast start/stop calls; `GameWsGateway` extended with four `@OnEvent` handlers; canonical event constants in `game-events.ts`; new unit tests cover emit ordering + payload shape + gateway broadcast behavior.
</objective>
