# Phase 06 — Deferred Items

Items intentionally postponed to later phases or phase verification. Logged here so they are not lost.

- [ ] socket.io Bun standalone-port workaround — the WS surface runs on a dedicated `WS_PORT=4101` standalone Socket.IO server with `transports: ['websocket']` + `allowUpgrades: false`, NOT attached to the games HTTP server. Root cause (P6.09, commit `c026012`): engine.io's `attach()` calls `server.listeners("request")` unconditionally, but Bun's `@nestjs/platform-express` HTTP server lacks the Node `EventEmitter.listeners()` method, throwing `server.listeners is not a function` and crash-looping the container. The standalone server's engine.io-owned `node:http` server DOES expose `.listeners()` on Bun, so the WS path works through Kong's `~/ws/?$` route → `games:4101`. This is a Bun-runtime constraint, not a design preference; documented as an ADR-022 consequence. Revisit if Bun's express adapter gains `EventEmitter.listeners()` or if the HTTP adapter changes — at that point the WS server could be re-attached to the main HTTP port. Low priority — the dedicated port works and is proven live.

- [ ] WS smoke probes 39 / 42 / 43 / 44 timing redesign (`scripts/smoke-health.sh`) — these four probes use timing-window assertions that collide with the autonomous round phase cadence and are brittle against round-timing race. Probe 39 (raw `GET /ws` curl Upgrade) fails by design — the standalone socket.io server expects the socket.io protocol, not a raw curl GET; it should use socket.io-client. Probe 42 (observe ≥30 ticks in a 2s window) needs the window to land inside RUNNING. Probe 43 (observe all 4 lifecycle events in 30s) needs a window wide enough for a full cycle. Probe 44 (REST bet → bet:my_active over WS in 5s) needs the round in BETTING within the probe window. Fix: replace fixed-window assertions with event-driven waits (await the next RUNNING phase, then count ticks; await the lifecycle event stream), and rewrite probe 39 to use socket.io-client. The WS path is functionally proven by probes 40 (handshake JWT-reject PASS) + 41 (snapshot-on-connect PASS) + the dedicated-port fix verification. Flagged for Phase 7 (FE client exists, can drive event-driven probes) or Phase 10 (smoke hardening).

- [ ] WS integration test suite broker-readiness (`services/games/tests/integration/ws-*.test.ts`) — the WS integration tests cannot run host-side because they resolve `rabbitmq:5672` (the Docker-internal hostname) which is not reachable from the host. The suite is authored and typechecks clean (`bunx tsc --noEmit -p tsconfig.integration.json`); live execution requires either running inside the games container's network or a broker-readiness helper that resolves the broker hostname + waits for the tunnel. Same class of issue as the Phase 5 integration-suite broker-readiness deferral. Fix candidates: (a) a `waitForBrokerReady` helper polling `amqplib.connect` before AppModule boot, (b) run the integration suite inside the container network in CI, (c) map the broker hostname for host-side runs. Flagged for Phase 10 (CI runs the full `docker:up` stack and can exercise the suite inside the network).
