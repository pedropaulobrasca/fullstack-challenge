<objective>
Unblock the browser tier before any FE code is written. Three infra/shared-contract changes that are invisible until the first browser request or the first `.tsx` money symbol:

1. **Kong CORS** — REST routes at `:8000` currently emit no CORS headers; a `fetch` from the SPA at `:3000` is cross-origin and the browser will block every balance/history/bet/cashout response (RESEARCH Pitfall 2 — `grep -c cors docker/kong/kong.yml` returns 0). Add a scoped Kong `cors` plugin.
2. **ESLint `.tsx` glob** — the `@crash/no-number-for-money` rule matches `**/*.ts` only; FE components are `.tsx` so the money guard silently does not apply to them (RESEARCH Pitfall 7). Extend the glob so REQ-DOM-06 is enforced in React components.
3. **Promote WS payload schemas to `@crash/contracts/ws`** — the zod schemas + types for every WS event live ONLY in `services/games/src/presentation/dtos/ws-event.payloads.ts` and are not importable by the FE (RESEARCH Pitfall 10 / Open Question 3). Promote them to a new `@crash/contracts/ws` subpath so both tiers share one source and cannot drift; have the games service re-export from contracts so there is exactly one definition.

Purpose: Each item is a hard blocker the planner must land before FE work — CORS gates every browser REST call, the eslint glob gates REQ-DOM-06 enforcement, and the shared schema prevents silent contract drift between server and client.
Output: CORS plugin in `kong.yml`; `.tsx` added to the money-rule glob; `@crash/contracts/ws` subpath exporting the WS payload schemas; `services/games` consuming the shared schemas via re-export.
</objective>
