The four spikes:
1. **SPA-mode boot (Pitfall 1, HIGHEST RISK):** `tanstackStart({ spa: { enabled: true } })` is reported to hang on the loading skeleton under Bun + Vite 7/8 (TanStack/router#5171). This project is Bun 1.3.11 + Vite 8 — squarely affected. Decide SPA mode vs default-SSR-with-`ssr:false`-on-the-game-route.
2. **oidc-spa two-instance parity (Open Question 1 / A1):** the React app uses `createReactOidc` (react-spa) and the socket singleton needs `createOidc` (core). Confirm both pointing at the same issuer/client share session/storage — or decide to export a single `getOidc()` from the react-spa instance instead.
3. **Workspace-TS import (Pitfall 8):** `@crash/contracts` and `@crash/shared-kernel` set `"main": "src/index.ts"` (raw TS, no build); Money VO imports `dinero.js/bigint`. Confirm Vite transpiles them (bun symlinked workspaces usually resolve, but verify) and that bigint targets are fine.
4. **Kong CORS reachability (Pitfall 2):** confirm the 07-01 CORS plugin actually lets a browser fetch from :3000 succeed against a REST route, or capture the exact failure to fix before FE work.

Purpose: Pitfall 1 alone can invalidate the entire scaffold approach — it must be answered first, blocking. The plan ends in a `checkpoint:decision` so the developer ratifies the boot mode (it changes the route-tree shape in 07-03).
Output: `frontend/spike/SPIKE-NOTES.md` recording the four DECISIONs; throwaway spike files.
