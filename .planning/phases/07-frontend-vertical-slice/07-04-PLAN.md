## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → Keycloak (OIDC) | Token acquisition/refresh; tokens in memory via oidc-spa |
| Browser → Kong WS handshake | Access token in auth.token; backend validates at handshake (Phase 6) |
| Inbound WS payloads | Server-sent but schema-validated client-side before mutating state |
| FE auth guard | UX-only redirect — NOT a security boundary; server re-validates every call (RESEARCH Security V4) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-08 | Information Disclosure | Access token in logs/console | mitigate | api.ts + socket auth never console.log the token; tokens stay in oidc-spa memory, not localStorage (RESEARCH Security V3/V7) |
| T-07-09 | Repudiation | Multi-tab refresh storm / desync | mitigate | oidc-spa built-in BroadcastChannel single-rotation (REQ-AUTH-03); no second refresh path (Pitfall 5) — `grep` confirms no hand-rolled BroadcastChannel/timer in auth/oidc.ts |
| T-07-10 | Tampering | Malformed/spoofed WS payload mutating state | mitigate | Every payload parsed via `@crash/contracts/ws` schema before apply; parse failure drops + warns (RESEARCH Pattern 3 / V5) |
| T-07-11 | Tampering | Trusting client-computed multiplier/payout for the cashout decision | mitigate | FE renders display only; cashout win/loss is server-authoritative (ADR-023); crash freeze uses server `crashPoint`, not interpolation (RESEARCH Security; Pitfall 4) |
| T-07-SC | Tampering | npm installs | accept | No new package installs (deps landed in 07-03); all Approved in RESEARCH audit |
</threat_model>
