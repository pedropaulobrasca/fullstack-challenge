<objective>
Build the left-rail money controls: the bet input with Money-VO validation + neutral Place Bet button (REQ-FE-04), the accent Cashout button with live bet×multiplier payout (REQ-FE-05), and the BETTING countdown (REQ-FE-06). These render from the 07-04 stores and mutate via the REST mutation hooks; they do NOT add any new plumbing.

Key discipline: bet amount and payout are Money VOs end-to-end — the input validates through the Money VO (REQ-DOM-06 now enforced in `.tsx` per 07-01), the wire body is a MoneySnapshot, and the live payout is `betAmount.multiplyRounded(currentMultiplier)` — never a JS `number`. The cashout payout subscribes to the isolated `multiplier.store.renderedMultiplier` (D-06) so the live label updates without coupling to the curve's rAF loop. All bounds and the betting duration come from config / `round.store`, never hardcoded.

Purpose: deliver the two money actions (bet, cashout) and the betting timer that make the loop playable, with state-aware enable matching the UI-SPEC State Matrix.
Output: `bet-amount.ts` pure validator + test; `use-place-bet`/`use-cashout` TanStack mutations; `bet-panel.tsx`, `cashout-button.tsx` (+ test), `countdown.tsx` components consuming the stores.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → Kong REST (bet/cashout) | Money amounts cross as MoneySnapshot; server re-validates bounds + balance authoritatively |
| Client-displayed payout | Display-only; the win/loss + actual credited payout is server-authoritative (ADR-023), never the client's bet×multiplier |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-12 | Tampering | Money typed as `number` in bet input/payout | mitigate | All amounts are Money VO via `parseBetAmount` + `multiplyRounded`; only the multiplier factor is a number; `@crash/no-number-for-money` (.tsx glob from 07-01) enforces at lint |
| T-07-13 | Spoofing | Client trusting its own bet×multiplier as the payout | mitigate | Live label is display-only; authoritative payout comes from `bet:my_cashed_out` WS snapshot (07-04); cashout decision is server-side (ADR-023) |
| T-07-14 | Denial of Service | Bet button spamming POST /games/bet | mitigate | Button disabled while `bet.store.pending` and once `myBet` exists; single active bet per round enforced server-side |
| T-07-SC | Tampering | npm installs | accept | No new package installs (deps + shadcn landed in 07-03) |
</threat_model>
