    ADR-024 (TanStack Start + oidc-spa, OIDC Authorization Code + PKCE S256): Context — the SPA must authenticate against Keycloak (`crash-game` realm, public PKCE client) with silent renewal and multi-tab coordination (REQ-AUTH-01/02/03); the realm is already PKCE-S256. Considered — (A) oidc-spa v10 (`createReactOidc` + `beforeLoadFn` guard + `createOidc` core accessor for the socket), (B) raw `oidc-client-ts`, (C) hand-rolled PKCE + refresh. Decision — oidc-spa: it provides PKCE, silent renewal, and BroadcastChannel multi-tab coordination as library configuration with zero hand-rolled token code; rolling these by hand burns days and is exactly the error-prone surface REQ-AUTH-03 stresses (Pitfall 5 refresh storm). Reference the 07-02 spike that confirmed instance parity and the 07-04 wiring (auth function reads `getTokens()` fresh per reconnect). Consequences — no hand-rolled refresh/broadcast path may be added (a second path causes storms); token lives in memory, not localStorage.

    ADR-025 (Canvas 2D for the crash curve): Context — the multiplier curve must render at 60fps with crisp retina output (D-05, REQ-FE-02, CLAUDE.md §Frontend). Considered — (A) Canvas 2D (rAF + devicePixelRatio + clearRect), (B) SVG path, (C) WebGL. Decision — Canvas 2D: SVG re-layouts the DOM per frame (jank at 60fps with a continuously-updating path), WebGL is overkill for a single 2D line and adds shader/context complexity with no payoff; Canvas 2D with dPR scaling + clearRect is the documented, sufficient, and lowest-complexity choice (locked in CLAUDE.md). Cite the 07-06 implementation (pure `draw-curve` + `use-raf-curve`). Consequences — no SVG/WebGL curve path; the renderer is reused by Phase 8 replay.

    ADR-026 (Zustand slice-per-concern, isolated multiplier store): Context — the 30Hz tick + 60fps rAF loop writes the rendered multiplier every frame; if that lived in a shared store, the bet panel / feed / history would re-render at 60fps (D-06, REQ-FE-03). Considered — (A) one shared store, (B) slice-per-concern with the multiplier rAF loop isolated to its own store. Decision — isolated multiplier store: only `CrashCurve` (and the cashout payout selector) subscribe to it, so high-frequency writes never re-render the panels (verified by the 07-04 dispatch test asserting `round:tick` touches only `multiplier.store`). Consequences — the tick handler must never write any other slice; new per-frame consumers subscribe to the multiplier store explicitly.

    ADR-027 (multi-tab refresh via oidc-spa BroadcastChannel): Context — REQ-AUTH-03 requires a single coordinated token rotation across tabs (no refresh storm). Considered — (A) oidc-spa's built-in BroadcastChannel election, (B) hand-rolled BroadcastChannel/localStorage-event coordination. Decision — use the library's built-in coordination; the 07-02 two-tab spike observed a single refreshing tab; adding a second mechanism reintroduces the storm (Pitfall 5). Consequences — `grep` in `auth/oidc.ts` must show no hand-rolled BroadcastChannel/timer; this ADR is the standing guard against a future plan adding one. (Note: this is the FE realization of the multi-tab intent the ROADMAP labeled "ADR-022" — that number is already used by Phase 6's tick/interpolation ADR, hence the renumber to ADR-027.)
