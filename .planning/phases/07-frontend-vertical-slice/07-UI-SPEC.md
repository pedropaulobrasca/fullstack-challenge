## Spacing Scale

8-point scale (all multiples of 4). Map to Tailwind v4 default spacing tokens.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps, inline chip padding, feed-row dividers |
| sm | 8px | Compact spacing inside cards, history-chip gaps |
| md | 16px | Default element spacing, card inner padding |
| lg | 24px | Rail padding, section padding, gap between curve and rails |
| xl | 32px | Layout gaps between major regions (desktop) |
| 2xl | 48px | Major section breaks, empty-state vertical centering |
| 3xl | 64px | Page-level top/bottom breathing room (desktop) |

**Exceptions:**
- Touch targets: interactive controls (Bet, Cashout, history chips on mobile) have a minimum hit area of **44×44px** (WCAG 2.5.5 / mobile). The visual element may be smaller but the tappable region is padded to 44px. This is the only deviation from the 4-multiple visual scale and applies to hit area only.
- Canvas region is fluid (fills available center-stage width), not snapped to the spacing scale.

## Typography

Two families, four roles. Numeric/value roles use **Fira Code with `font-variant-numeric: tabular-nums`** so the multiplier and money do not reflow as digits change at 60fps (critical for the counting multiplier and balance counter-up).

| Role | Family | Size | Weight | Line Height | Tabular nums |
|------|--------|------|--------|-------------|--------------|
| Display (live multiplier) | Fira Code | 64px (mobile 44px) | 600 | 1.0 | yes |
| Heading (round state, payout, balance) | Fira Code | 28px | 600 | 1.2 | yes |
| Body (feed rows, labels, helper) | Fira Sans | 16px | 400 | 1.5 | n/a |
| Label (chips, button text, captions, countdown unit) | Fira Sans | 14px | 600 | 1.4 | n/a |

- **Exactly 2 weights**: regular (400) + semibold (600). No light/bold proliferation.
- The multiplier Display is rendered **on the Canvas** (rAF, not DOM) per D-05; its font is set via `ctx.font = "600 {px}px 'Fira Code', monospace"` to match the DOM type ramp. Money/payout/countdown stay in the DOM.
- History crash-point chips use the Label role (14px Fira Code, tabular) so `1.04x` and `12.50x` align.

## Color

60 / 30 / 10 split on a deep-black base. Adapted from ui-ux-pro "Victory Surge" (No.81) gaming semantic tokens, constrained by locked decision D-02.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#0A0F14` | App background, canvas backdrop — OLED-deep black |
| Secondary (30%) | `#111827` (cards) / `#1F2937` (popover/elevated) | Bet panel rail, live-feed rail, history strip, modals, skeleton base |
| Accent (10%) | `#00FF85` → `#22D3EE` (emerald→cyan neon) | See reserved-for list below |
| Destructive | `#EF4444` | **Crash state ONLY** (see discipline note) |
| Border / hairline | `#1E3A5F` | Card borders, rail dividers, input outline (rest state) |
| Muted foreground | `#94A3B8` | Secondary text, masked player ids, timestamps, disabled labels |
| Foreground | `#F8FAFC` | Primary text on dark surfaces |

**Accent reserved for (emerald `#00FF85` → cyan `#22D3EE`):**
- The rising multiplier curve + its glow while `RUNNING` below crash
- The live multiplier number while rising
- The Cashout button (primary CTA during RUNNING with an active bet)
- Cashout-win confirmation (own-bet feed highlight, payout flash, confetti tint)
- "Live" / connected status dot
- Own-action highlight rail accent in the live feed
- Positive history chips (`> 2.0x` green band uses the emerald end of the accent ramp)

NOT used for: generic hover states, all borders, every button. The Bet (placement) button is a **neutral/secondary** treatment (elevated surface + border + foreground text), NOT accent — accent is the reward/rising signal, kept scarce so the cashout moment pops.

**Destructive / red discipline (D-02 — non-negotiable):**
`#EF4444` red is reserved EXCLUSIVELY for the **crash** state: the crash flash overlay, the frozen crashed multiplier value, the `round:crashed` feed entries, and the `≤ 1.5x` history band. Red is NEVER used for form-validation errors, the Bet button, or generic destructive UI. Validation/error affordances use `muted-foreground` + the toast surface (amber `#F59E0B` permitted for non-crash warnings/toasts only, e.g. insufficient balance, network) — keeping red unambiguous so a flash of red always means "crash."

**History strip color bands (REQ-FE-08, env-tunable thresholds):**
| Band | Multiplier | Color | Token source |
|------|-----------|-------|--------------|
| Low | `≤ HISTORY_RED_MAX_X` (default 1.5x) | red `#EF4444` | shares crash hue — acceptable, semantically "bad outcome" |
| Mid | between (default 1.5x–2.0x) | amber `#F59E0B` | warning band |
| High | `> HISTORY_YELLOW_MAX_X` (default 2.0x) | emerald `#00FF85` | accent ramp |

Thresholds are **env/config-driven** (e.g. `VITE_HISTORY_RED_MAX_X=1.5`, `VITE_HISTORY_YELLOW_MAX_X=2.0`) — NOT hardcoded (per CLAUDE.md "no hardcoded business constants"). Materialize in `.env.example` + frontend typed config during planning.

**Glow / neon treatment (restrained, per D-04):** rising curve + cashout win may use a single soft glow — `box-shadow: 0 0 24px rgba(0,255,133,0.35)` / `text-shadow: 0 0 12px rgba(0,255,133,0.5)` (from the MCP `Glow_Effects` field). One glow layer max. No scanline/glitch overlays (the MCP cyberpunk style block is explicitly rejected as too loud for senior polish).

## Layout Contract (D-01 — Stake/Aviator center-stage + side rails)

**Desktop (≥ 1024px):**
```
┌────────────────────────────────────────────────────────────┐
│ Header: logo · "Fairness ✔" placeholder* · wallet balance pill · user │
├──────────────┬───────────────────────────────┬─────────────┤
│              │   History strip (last 20 chips, horizontal)   │
│  Bet panel   │ ┌───────────────────────────┐ │  Live feed   │
│  (left rail) │ │                           │ │ (right rail) │
│  - amount in │ │   CANVAS CURVE (60fps)    │ │  bet:placed  │
│  - Bet btn   │ │   live multiplier (center)│ │  cashed_out  │
│  - Cashout   │ │   countdown overlay       │ │  own = accent│
│    btn       │ │   crash flash/freeze      │ │  scroll-area │
│              │ └───────────────────────────┘ │              │
└──────────────┴───────────────────────────────┴─────────────┘
```
\* the "Fairness ✔" badge is **Phase 8** — reserve header space only, do not implement the drawer here.

- Center stage (curve) is the dominant region per MCP KPI-hierarchy guideline No.100 ("most important largest & central"). The live multiplier is the single largest element on the page.
- Left rail width ~320px; right rail width ~320px; rails use Secondary surface `#111827` with `#1E3A5F` hairline borders.
- Gap between regions: `lg` (24px); page padding `xl` (32px) top, `lg` sides.

**Mobile (< 768px) — single stacked column (D-01):**
order: history strip → curve (reduced height, ~40vh) → controls (bet + cashout) → live feed (capped height, scroll). Controls are sticky-bottom on mobile so Bet/Cashout stay thumb-reachable. Rails collapse into full-width stacked cards.

**Breakpoints:** Tailwind defaults — `sm 640 / md 768 / lg 1024 / xl 1280`. Two-rail layout at `lg+`; stacked below.

## State Matrix (the slice must render correctly in every state)

| Surface | BETTING | RUNNING | CRASHED | SETTLED/cooldown |
|---------|---------|---------|---------|------------------|
| Curve | flat baseline + countdown overlay | rising emerald→cyan curve + live multiplier | red flash → frozen value + brief freeze overlay | curve fades, "next round in Ns" |
| Bet button | **enabled** (unless player already has active/pending bet → disabled w/ reason) | disabled | disabled | enabled when next BETTING opens |
| Cashout button | hidden/disabled | **enabled** iff own bet ACTIVE; shows live payout | disabled (too late = 409 handled silently) | hidden |
| Live feed | bets streaming in | cashouts streaming + own highlight | final crash entry (red) | quiet |
| History strip | unchanged | unchanged | new chip prepended on crash | unchanged |
| Balance | static | static | static | counter-up if cashout credited |

**Empty / loading / error states (REQ-FE-13):** every async surface has a skeleton (history fetch, initial snapshot wait) and an empty state (see copywriting). Toasts are deduped by message key.

## Juice / Motion Budget (D-04 — restrained, senior-polished)

Four sanctioned juice moments. **No screen shake. No heavy particle storms.** Honor `prefers-reduced-motion` (disable confetti + flash, keep instant state change).

| Moment | Treatment | Budget |
|--------|-----------|--------|
| Balance change | counter-up tween (Fira Code tabular, ~400ms ease-out) | REQ-FE-14 |
| Cashout win | accent glow pulse on Cashout/payout + **small** confetti burst (≤ ~40 particles, ~800ms, emerald/cyan tint) | REQ-FE-14; single burst, no loop |
| Crash | red flash (≤ 200ms fade) + brief freeze overlay (~600–800ms) holding the crashed value | REQ-FE-14; freeze, not shake |
| Rising curve | soft emerald→cyan glow that intensifies subtly with multiplier; single shadow layer | D-04; no trails/storms |

Confetti library is Claude's discretion (per CONTEXT) — pick a lightweight one (e.g. `canvas-confetti`), gate behind reduced-motion. Curve EWMA alpha constant must be **env/config-driven** (per CONTEXT discretion — confirm value in planning, do not hardcode).

## Copywriting Contract

UI copy is **English** (Out-of-Scope excludes i18n). Casino-confident but not gaudy.

| Element | Copy |
|---------|------|
| Primary CTA — placement | **"Place Bet"** (disabled-while-active label: "Bet Active") |
| Primary CTA — cashout | **"Cash Out {liveMultiplier}x · {payout}"** (e.g. "Cash Out 2.41x · 24.10 CRD") |
| Login redirect CTA | **"Log in to play"** |
| Countdown label | "Betting closes in {n}s" |
| Running label | "{multiplier}x" (the value IS the headline) |
| Crashed label | "Crashed @ {crashPoint}x" |
| Empty state — live feed heading | "No bets yet this round" |
| Empty state — live feed body | "Place a bet during the betting window to see the action here." |
| Empty state — history heading | "No rounds yet" |
| Empty state — history body | "Crash history will appear after the first round settles." |
| Error — insufficient balance | "Not enough balance. Lower your bet or wait for a win." |
| Error — bet rejected (window closed) | "Betting window closed — your bet was refunded." |
| Error — network / WS drop | "Connection lost. Reconnecting…" (auto-clears on resync) |
| Error — cashout too late | (no toast — handled silently; bet resolves as LOST via crash) |
| Loading — round in flight | (skeleton; no text) |
| Loading — history fetch | (skeleton chips; no text) |

**Destructive actions in this phase:** none in the irreversible sense. Placing a bet and cashing out are the only money actions; both are intentional, single-tap, and **do not require a confirmation dialog** (a confirm step would break the real-time tactile loop the phase exists to deliver). The betting-window time limit is itself the natural guard. No `AlertDialog` destructive confirmation is specified for P7.

## Accessibility & Real-Time Discipline

- Contrast: foreground `#F8FAFC` on `#0A0F14`/`#111827` exceeds WCAG AA; accent emerald on dark exceeds AA for large text (multiplier is large). Verify the Cashout button label contrast against the accent fill (use `#0A0F14` text on emerald fill, not white).
- `prefers-reduced-motion`: disables confetti, crash flash, counter-up (snap instead). Curve still renders (it is content, not decoration) but glow is reduced.
- The 60fps rAF loop writes ONLY to its isolated Zustand slice (D-06) — bet panel, feed, history do not re-render per frame.
- Tabular numerics everywhere a value changes rapidly (multiplier, balance, payout) to prevent layout shift.
- Touch targets ≥ 44px (see Spacing exceptions).
