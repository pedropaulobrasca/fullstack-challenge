<objective>
Land the `autoCashoutTarget` field on the Bet aggregate end-to-end (domain → entity → migration → DTO → use case → repository query method). This is the foundation Plan 09-05 (AutoCashoutTickService) reads from. The change is additive and backwards-compatible: existing manual POST /games/bet calls (no autoCashoutTarget) continue to 202.

Output: Bet aggregate with optional Multiplier field; MikroORM entity + migration with INT centiX column + indexed partial WHERE clause; nestjs-zod DTO validation; new repository method optimized for per-tick query.
</objective>

## Trust Boundaries

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-05 | Tampering | Player forges autoCashoutTarget below 1.01x or above 100.00x | mitigate | Zod schema enforces `.min(env.AUTO_BET_MIN_TARGET_CENTI_X / 100).max(env.AUTO_CASHOUT_MAX_X)` at controller entry; 400 Bad Request before saga begins. Server is the trust boundary per ADR-023 generalization. |
| T-09-06 | Tampering | Player forges non-numeric or NaN autoCashoutTarget | mitigate | `z.number().positive()` rejects non-numerics; `.optional()` makes the field omittable but never empty-string-coercible. |
| T-09-07 | Information Disclosure | findAutoCashoutCandidates leaks bet rows from other rounds | mitigate | Query is parameterized on `roundId` (branded RoundId) + `status='ACTIVE'`; cannot cross-query other rounds. The DB index also enforces the WHERE predicate at the storage layer. |
| T-09-08 | Tampering | Migration accidentally introduces a writable mutation path for autoCashoutTarget (e.g., a PATCH endpoint) | mitigate | This plan adds ONLY a column + a SELECT method; no write path beyond initial Bet.place(). Code review gate. |
| T-09-09 | Repudiation | An auto-cashout bet's target is altered post-placement | mitigate | The autoCashoutTarget is set at Bet.place() time, immutable thereafter (no setter; field is `private readonly`). The Bet aggregate's existing FSM-guarded behavior methods do not touch this field. |
</threat_model>
