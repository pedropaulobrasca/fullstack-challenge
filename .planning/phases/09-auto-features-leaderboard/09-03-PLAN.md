| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-09-11 | Spoofing | A malicious actor injects fake bet.lost messages into the RabbitMQ exchange | mitigate | RabbitMQ access is broker-trust within the Docker network (no external connectivity per Phase 5 design). All publishes come from the games-service outbox; consumers do not validate cryptographic provenance. |
| T-09-12 | DoS | SettleRoundUseCase emits an unbounded number of bet.lost rows on a runaway round with many bets | accept | Bounded by the per-round bet count; the existing Phase 4 partial unique index `bets_one_active_per_player` caps at one bet per player per round. Even in a high-traffic round, total bet count is bounded by active player count. |
| T-09-13 | Tampering | The new outbox path opens a window for a stale bet.lost to be published twice (TX retry) | mitigate | em.transactional with serializable isolation + Phase 2 outbox publish-once contract; messageId is uuid v4 generated at envelope build time, fresh on each emit. |
