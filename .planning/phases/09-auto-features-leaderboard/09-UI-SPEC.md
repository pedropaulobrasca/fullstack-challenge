**Adaptation vs Phase 7/8 inherits:**
- The MCP "Sales Intelligence Dashboard" entry suggests `--rank-1-color: #FFD700` (gold), `--rank-2-color: #C0C0C0` (silver), `--rank-3-color: #CD7F32` (bronze). The Phase 7/8 dark-casino palette **rejected gold** (D-02 in Phase 7 reserves accent emerald→cyan and red exclusively for crash). The Phase 9 leaderboard therefore **does NOT introduce medal hues as fills**; instead the top-3 ranks are differentiated using the **inherited semantic ramp**: rank 1 = `accent` emerald `#00FF85` left-border + rank chip with low-alpha accent surface, rank 2 = accent cyan `#22D3EE` left-border (the second accent ramp end), rank 3 = `muted-foreground` `#94A3B8` left-border (neutral). Ranks 4-10 = `border` `#1E3A5F` hairline, no accent. This keeps the recruiter-defensible "accent is scarce, only the rising/winning signal" discipline from Phase 7/8.
- The MCP "Sales Intelligence" pattern uses "leaderboard ranking changes" as an animation. Per CONTEXT discretion ("rank-up animation if any (must be reduced-motion gated and stay within the 4-juice budget — leaderboard rank-up does NOT add a new juice moment, just a subtle border or a chip transition")) — the rank-up is implemented as a **200ms border-color transition** on the rank chip (low-alpha accent flash for ~600ms then settles back), reduced-motion gated to snap. This is a UI transition (sub-300ms band per MCP), explicitly NOT a juice moment, no count against the 4-budget.
- Phase 8 introduced the scrim overlay; Phase 9 introduces **no new overlay**. Both new surfaces are tab-swapped content inside existing rails at `z-0`. The z-stack is byte-identical to Phase 8.

### Auto-tab Start/Stop button color discipline

| Button state | Variant | Surface | Border | Text | Notes |
|---|---|---|---|---|---|
| Idle (form invalid) | shadcn `Button` `variant="default"` disabled | `--secondary` `#1F2937` | none | `muted-foreground` | opacity-50 + `cursor-not-allowed`; label `Start auto-bet`; lucide `Play` icon `muted-foreground` |
| Idle (form valid) | `variant="default"` | `accent` emerald `#00FF85` | none | `#0A0F14` (dark foreground on accent fill, contrast verified) | label `Start auto-bet`; lucide `Play` icon dark; `active:scale-95` press feedback |
| Running | `variant="outline"` | transparent | `destructive` `#EF4444` 1px (border only — fill stays surface) | `destructive` `#EF4444` | label `Stop auto-bet`; lucide `Pause` icon `destructive`; this is the ONE pre-approved use of the destructive token outside of crash (it's a destructive-affordance border, NOT a destructive fill — the user reads it as "halt the running process") |
| Loading (first round post-Start, awaiting `bet:my_active`) | `variant="default"` disabled | `accent` (same as idle valid) | none | `#0A0F14` | label `Starting…`; lucide `Loader2` `animate-spin` icon; cleared once the first bet transitions to ACTIVE |

The destructive border (NOT fill) on the Stop button is the single concession to using `#EF4444` outside of crash. The visual weight stays low because the surface is the same secondary `#1F2937`; only the 1px border + text are destructive-toned. This is justified because:
- The action IS destructive (halts an automated process).
- A fully destructive fill would compete with the crash flash visually.
- A border-only treatment keeps the "red = crash" semantic dominant while still signalling "halt".

### Manual-tab-disabled-while-running affordance

The Manual `TabsTrigger` stays **clickable** (so the user can SEE the disabled state and the explainer — clicking a disabled trigger would prevent that), but the Manual `TabsContent` body is:
- `opacity-50` on the BetPanel form (per MCP "Disabled States" sev:Medium rule)
- `cursor-not-allowed` on all form inputs
- inputs are `disabled` (HTML attribute) + `aria-disabled="true"`
- an inline `Alert` (shadcn) variant=`default` (NOT destructive) appears at the top of the Manual `TabsContent` with lucide `Lock` icon, `accent` border (so it's noticeable but not alarming), copy: `"Auto-bet is running. Switch to the Auto tab to stop."`
- the Manual `TabsTrigger` itself shows a small lucide `Lock` icon 12px in `muted-foreground` to the right of the `Manual` label, signalling the locked state without preventing tab navigation.

### Accent additions (already reserved-for in P7/P8, now also reserved for)

- Auto-tab Start button fill (idle-valid state) — `accent` emerald (a CTA-shaped affordance, consistent with the Phase 7 Cashout-button rule that the reward/start signal gets the accent).
- Leaderboard rank-1 chip surface + border + rail; rank-2 chip surface + border + rail (cyan end of the accent ramp).
- Leaderboard own-row left-rail (always emerald, regardless of rank — mirrors the Phase 7 own-bet feed-row accent rail).
- Manual-tab-disabled `Alert` border (so the explainer is noticed, not hidden in muted noise).
- Rank-up transient border flash on a rank chip whose rank improved (200ms ease-out, reduced-motion snap).

### Destructive additions (already reserved for crash in P7/P8)

- Auto-tab Stop button border + text (border-only, NOT fill — single concession explained above).

No other Phase 9 surface uses destructive `#EF4444`. Form validation errors use `muted-foreground` text below the input (NOT red); negative leaderboard profit uses `muted-foreground` + `TrendingDown` icon (NOT red); a saga-rejected auto-bet uses the existing Phase 7 amber warning toast (NOT red).

#### Rank-up transition (NOT a juice moment, just a 200ms border transition)

Per CONTEXT discretion ("rank-up animation [...] does NOT add a new juice moment, just a subtle border or a chip transition"):

- When a `leaderboard:updated` event arrives and a row's rank IMPROVED (e.g. rank 4 → rank 2), the rank chip's border briefly flashes to `accent` (`#00FF85` for any rank-up regardless of new rank) for 200ms, then transitions back to its rank-color border over another 600ms ease-out. The row background does NOT flash (to avoid the cashout-celebration competitive signal).
- Rank-down (e.g. rank 2 → rank 4) does NOT animate. Falling out of the top 3 should not flash. This keeps the animation reserved for positive signal only — consistent with the Phase 7 emerald = "rising/winning" discipline.
- Under `prefers-reduced-motion: reduce`: the border color snap-changes to its new rank-color value, NO transition. The reduced-motion user still SEES the rank change (the rank number is the source of truth, not the animation).
- This is a **CSS transition on `border-color`**, NOT a JS-animated effect. No new dependency, no new framework hook.
- Budget classification: **UI transition (sub-300ms entrance band per MCP "animation duration ease micro-interaction" Result 1)**, NOT a juice moment. The Phase 7 four-juice budget (counter-up, confetti, crash flash/freeze, rising glow) is unchanged.

## Accessibility & Real-Time Discipline (Phase 9 specifics)

- **Inputs always have labels** (MCP "Input Labels" sev:High, "Form Labels" sev:High): every Auto-tab input has a `<Label htmlFor=...>` above it. Placeholders are NOT used as labels.
- **Inline validation on blur** (MCP "Inline Validation" sev:Medium): not on every keystroke (too noisy for currency typing), not only on Start click (too late). Errors render below the input in `muted-foreground` (NOT red — red is reserved for crash per inherited D-02), wired via `aria-describedby`.
- **Disabled states clearly indicated** (MCP "Disabled States" sev:Medium): `opacity-50 cursor-not-allowed` + `aria-disabled="true"` + HTML `disabled` on every disabled input/button. The Manual-tab-disabled-while-running treatment goes further by adding an inline explainer `Alert` so the user knows WHY (per the MCP rule "Don't confuse disabled with normal state" — the explainer prevents the user from thinking the form is broken).
- **Strategy radio group** has proper grouping via shadcn `RadioGroup` (Radix-backed, ARIA role=radiogroup with aria-labelledby pointing to the `Strategy` label).
- **Tab triggers are keyboard-navigable** (shadcn `Tabs` is Radix-backed): left/right arrows switch tabs, Home/End jump to first/last, Tab moves into the active `TabsContent`. Focus rings inherited from Phase 7/8.
- **Touch targets ≥ 44px** (MCP "Touch Target Size" CRITICAL): tab triggers, all Auto-tab inputs, Start/Stop button, RadioGroup items, Leaderboard refresh button. Leaderboard rows are non-interactive in v1 but maintain 44px+ height for visual density.
- **Leaderboard rank announcement**: the rank-up transition is visual-only; for screen readers, the new rank is read out via an `aria-live="polite"` region inside the LeaderboardPanel that announces `"You moved up to rank {n}"` when own-rank improves (no announcement on rank-down, mirroring the visual treatment). Other players' rank changes are not announced (would be noisy).
- **Net profit color rule never conveys by color alone** (MCP "Color Only" sev:High from Phase 8 grounding): every positive/negative profit has its `TrendingUp` / `TrendingDown` lucide icon + leading `+` / `−` sign. Color is the third channel, not the only channel.
- **Stop-win / Stop-loss halt is announced** via the existing Phase 7 dedupedToast (amber warning surface), so screen-reader users hear the halt reason even if the Auto tab is not focused.
- **Auto-bet config locked while running**: this is intentional — changing config mid-session would invalidate the cumulative P/L calculation (per D-01 stops are cumulative since Start). The `disabled` HTML attribute + `aria-disabled="true"` are the a11y signal; the Stop button is the escape hatch.
- **Background game preserved** during tab swap: the rAF loop, WS connection, round FSM keep running regardless of which tab is active in either rail. This is the discipline that makes the tabbed approach safe.
